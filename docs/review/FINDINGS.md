# Результаты первоначального ревью

Статус R1–R9: исправления внесены в рабочую копию 2026-10-29. Регрессионные проверки и ограничения в [FIXES.md](FIXES.md). Ниже сохранено исходное описание дефектов; номера строк относятся к первоначальной базе.

База и границы проверки — в README.md. P1 — блокировка прогресса, P2 — ошибка поведения, P3 — ограниченный дефект API. R1–R5 подтверждены запуском `reproduce.gd`; остальные — статический анализ, без утверждения о выполненной платформенной проверке.

## R3 · P1 · Сохранение во время звонка блокирует прогресс

`scripts/quest_item.gd:95` выставляет is_phone_answered до завершения диалога; дверь открывается только в `_on_dialogue_finished` (177). Quicksave разрешён во время разговора (`pause_menu.gd:208`). SaveManager сохраняет answered=true/door_opened=false. При загрузке `set_phone_state` отключает обработчик завершения, затем диалог отменяется. После загрузки дверь заперта, телефон уже отвечен, повторно начать разговор невозможно.

Воспроизведение: новая игра → взять трубку → сохранить до конца разговора → загрузить. Проба подтверждает answered=true, door=false, UI inactive. Исправление: сохранять стадию квеста/диалога либо запрещать сохранение до согласованной контрольной точки. Проверить загрузку из меню и внутри комнаты.

## R1 · P2 · Новая игра наследует улики и выводы

`scripts/main_menu.gd:213` сбрасывает inventory/paranoia, но не вызывает существующий `ClueManager.reset_all_clues` (`clue_manager.gd:377`). Autoload переживает смену сцены. `main.gd:8` также не сбрасывает улики.

Найти улику → меню → новая игра: улика остаётся открыта; аналогично выводы. Проба подтверждает receipt. Сбросить состояние новой сессии централизованно; проверять и открытые дедукции.

## R2 · P2 · Сохранения не восстанавливают предметы мира

`scripts/pills_item.gd:90` удаляет узел через queue_free. `save_manager.gd:296` загружает сохранение в существующую сцену, а `apply_pending_save_if_any:323` восстанавливает inventory, но не мир.

Сохранить до подбора → подобрать таблетки → загрузить: инвентарь пуст, таблетки отсутствуют. Обратный сценарий (сохранение после подбора → загрузка из меню) создаёт предмет заново и позволяет повторный подбор. Проба подтверждает первый сценарий. Хранить ID подобранных предметов и восстанавливать их вместе с инвентарём либо реконструировать сцену из полного состояния. Тот же аудит нужен для has_been_inspected и фонарика.

## R4 · P2 · «Отменить изменения» не откатывает клавиши

`scripts/settings_manager.gd:66` читает сохранённые keybinds, но не очищает custom_keybinds и не восстанавливает InputMap перед чтением. `revert_settings:211` лишь вызывает load_settings/apply_settings. Если в JSON нет action, новая несохранённая клавиша остаётся.

На чистых настройках переназначить move_up на Z → отменить: действие всё ещё Z. Проба подтверждает. Перед загрузкой восстановить полный исходный набор событий и заменить словарь пользовательских привязок. Отдельно проверить сброс к defaults: сейчас он оставляет только первую клавишу и теряет вторичные клавиши (стрелки).

## R5 · P3 · Отрицательное удаление увеличивает количество

`scripts/inventory_manager.gd:52` не проверяет count > 0. remove_item(id, -2) для количества 1 возвращает true и оставляет 3. Проба подтверждает. Текущие UI-вызовы передают положительное значение; это дефект контракта API, не доказанный эксплойт игрока. Добавить проверку на границе метода.

## R6 · P2 · Старые сохранения наследуют текущие улики (статически)

`scripts/save_manager.gd:371` пропускает загрузку при пустом clues_data; `ClueManager.load_save_data:349` обновляет только переданные ключи. Встроенные demo saves не содержат clues. Загрузка такого слота после исследования сохраняет прежние улики и дедукции, хотя квест и позиция откатились. Нужен полный reset перед восстановлением, миграция версии и явные значения по умолчанию. Не ограничиваться исправлением R1.

## R7 · P2 · Отмена осмотра считается завершением (статически)

`scripts/dialogue_box.gd:593` испускает dialogue_finished даже при cancel_dialogue во время загрузки. Улики подписаны на этот сигнал (`interactive_clue.gd:216`), и `_on_inspection_finished:244` открывает улику. SaveManager отменяет диалог до восстановления clues, так что возможны ложные уведомления/побочные эффекты, а для старых сохранений без clues — сохранение ложной находки. Разделить завершение и отмену, отключать обработчики перед восстановлением состояния.

## R8 · P2 · Отключённые клавиши продолжают работать (статически)

`player.gd:58` при нулевом InputMap всё равно читает WASD/стрелки напрямую. Аналогично жёсткие альтернативы есть в flashlight, quest_item, interactive_clue и pause_menu. `dialogue_box.gd:633` проверяет H напрямую, игнорируя настраиваемое toggle_history. После переназначения старые кнопки остаются активны или вызывают сразу несколько действий. Использовать InputMap как единый источник и отображать подсказки из него.

## R9 · P2 · Windows-сборка привязана к машине автора (статически)

`build_installer.bat:6`, `build_installer.ps1:7`, `installer.iss:20`, `tools/index_codebase.ps1:4` используют абсолютные C:\Users\ilya и e:\kamdraaa-game. На другом checkout штатные команды не работают. SetupIconFile требует build/dist/app_icon.ico, хотя копирование иконки условное и исходный build игнорируется Git. Параметризовать инструменты, вычислять корень относительно скрипта, обеспечить иконку. Windows-сборка не выполнялась.

## Дополнительные риски и долг

- SaveManager проверяет только верхний Dictionary; вложенные player/quest/clues/inventory не валидируются. JSON правильного синтаксиса с неверными типами может оборвать загрузку. Запись в существующий файл не атомарна; сбой во время записи может уничтожить слот. Нужны схема/версия, временный файл и обработка ошибок.
- На первом запуске создаётся демонстрационный autosave с открытой дверью. Continue выбирает по mtime и может начать с демонстрационного прогресса. Требует решения, должны ли демо-сохранения попадать в пользовательскую игру.
- ParanoiaManager работает ALWAYS: стресс продолжает спадать в паузе, хотя мир стоит. Нужна явная продуктовая политика паузы.
- DarknessAnxiety вызывает relief в body_exited и повторно в следующем _process через _was_in_darkness: вероятное двойное снижение на 15. Нужна отдельная проба перехода области.
- Большие main_menu/pause_menu дублируют настройки и карточки; риск расхождения. Выделять общие компоненты после исправления поведения, без массового рефакторинга ради стиля.
- Шейдер дождя многократно вычисляет город/капли на пиксель; процедурные WAV и текстуры создаются на CPU. Без профилирования GPU/CPU это зоны измерения, не доказанные проблемы производительности.
- ObjectDB leak при выходе подтверждён логом, источник не диагностирован. Не приписывать его конкретному компоненту без verbose и сравнения после очистки.

Порядок исправления: R3 → R1/R2/R6/R7 как единый аудит состояния → R4/R8 → переносимость сборки → защита API и сохранений. После каждого изменения пересмотреть связанные записи, хеши и пробы.
